#### 1、load-use冲突怎么解决
- **什么是load-use冲突**
    ```
    lw x1,0(x2) # 从x2读数据写回x1

    add x3,x1,x4 # 用x1的值做加法
    ```

- **Load-Use指令（LW -> ADD）为什么 Bypass 不行？**

    ```Plaintext
    Cycle:      1     2     3     4     5
    lw  x1...  [IF]  [ID]  [EX]  [MEM] [WB]  <-- x1 的数据要到 MEM 阶段末尾 (Cycle 4) 才能从内存读出来！
    add ...,x1       [IF]  [ID]  [EX]  [MEM] <-- add 在 EX 阶段开头 (Cycle 4) 就必须要拿到 x1！
                                ^
                                | (此时 x1 还在内存里没读出来！！)

    ```
    add 指令需要在 Cycle 4 的开头（EX 阶段） 拿到 x1 的值进行 ALU 加法计算。

    但是 lw 指令的数据必须去内存 RAM 里“走一圈”，要到 Cycle 4 的末尾（MEM 阶段） 才能真正读出数据！

- **解决方法**

    CPU 强制暂停（Stall）流水线 1 拍，给 lw 指令争取时间去读内存：

    ```Plaintext
    Cycle:      1     2     3     4     5     6
    lw  x1...  [IF]  [ID]  [EX]  [MEM] [WB]  
                                | (数据在 Cycle 4 末尾读出)
                                v  (此时可以顺利前递了!)
    add ...,x1       [IF]  [ID]  [ID]  [EX]  [MEM] [WB]  <-- 强制在 ID 阶段卡住了 1 拍！
                        (Stall)
    ```
    在 Cycle 4，硬件检测到了 Load-Use 冲突，触发 stall = 1。

    add 指令被扣留在 ID 阶段（就是我们前一段代码中 inst_PC_reg 和 instruction 被 hold 冻结住的那一拍）。

    到了 Cycle 5，lw 进入 MEM 阶段末尾，x1 的真实数据终于吐出来了！

    此时，硬件通过 Bypass 把 MEM 阶段读出的数据直接前递给正在 EX 阶段的 add 指令。

#### 2、为什么IF_ID阶段需要flush两个周期 ⚠️

因为IMeme是同步读，rdata滞后addr一拍

```verilog
always_ff @(posedge clk) begin
    if (ibus.req && gnt && ...) rdata_q <= mem[mem_addr];   // 地址在沿 K 送，数据沿 K+1 才出
end

```
地址送出去后，数据要下一拍才会出现在rdara_q
```
沿 K:   PC_reg = A            （地址送出去）
沿 K+1: rdata_q <= mem[A]      （数据出来，inst_PC 也跟到 A）
沿 K+2: IF/ID <= {mem[A], A}   （IF/ID 才锁存这条指令）
```

假设指令I_A（地址A）在EX阶段判定分支成立，目标为target,顺序取值假设PC=A,A+4,A+8……

```
沿 N:   PC_reg=A                    取 A             IF的第一拍 地址请求进入IF       
沿 N+1: rdata_q=mem[A], inst_PC=A,   PC_reg=A+4      IF的第二拍 同步读出数据
沿 N+2: IF/ID<=I_A,                  PC_reg=A+8     （I_A 进 ID）
沿 N+3: ID/EX<=I_A, IF/ID<=I_{A+4},  PC_reg=A+12    （I_A 进 EX）
沿 N+4: ★ 分支解析：PC_reg<=TARGET
        IF/ID 被 flush（清掉正要锁存的 I_{A+8}）
        ID/EX 被 flush（清掉正要锁存的 I_{A+4}）
        I_{A+12}去同步读 mem[A+12]
        I_TARGET进入IF第一拍 PC_reg=target
沿 N+5: IF/ID 被 flush（清掉刚到达锁存点的 I_{A+12}）   ← 这就是第 2 拍
        I_TARGET进入IF第二拍 mem[TARGET]
沿 N+6: IF/ID<=I_TARGET             （正确指令）

```
把它逐条对应到 IF 的三拍位置上：
```
沿	PC_reg（第 1 拍）	rdata_q（第 2 拍）	IF/ID（第 3 拍）
N+3	更新为 A+12	—	锁存 I_{A+8}
N+4	更新为 TARGET（跳转）	锁存 mem[A+12]	flush（丢 I_{A+8}）
N+5	= TARGET	锁存 mem[TARGET]	flush（丢 I_{A+12}）
N+6	= TARGET+4	锁存 mem[TARGET+4]	锁存 I_TARGET
```
个人理解：IMem对于跳转无感知，照常往IF_ID送，只能在IF_ID_reg对数据进行flush

这个和几级流水线无关，和IMem的设计有关
