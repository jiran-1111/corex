### 20260813

#### 1、load-use冲突怎么解决
- **什么是load-use冲突**
    ```
    lw x1,0(x2) # 从x2读数据写回x1

    add x3,x1,x4 # 用x1的值做加法
    ```

- **Load-Use指令（LW -> ADD）为什么 Bypass 不行？**

    ```Plaintext
    Cycle:      1     2     3     4     5
    lw  x1...  [IF]  [ID]  [EX]  [MEM] [WB]  <-- x1 的数据要到 MEM 阶段末尾 (Cycle 4) 才能从内存读出来！
    add ...,x1       [IF]  [ID]  [EX]  [MEM] <-- add 在 EX 阶段开头 (Cycle 4) 就必须要拿到 x1！
                                ^
                                | (此时 x1 还在内存里没读出来！！)

    ```
    add 指令需要在 Cycle 4 的开头（EX 阶段） 拿到 x1 的值进行 ALU 加法计算。

    但是 lw 指令的数据必须去内存 RAM 里“走一圈”，要到 Cycle 4 的末尾（MEM 阶段） 才能真正读出数据！

- **解决方法**

    CPU 强制暂停（Stall）流水线 1 拍，给 lw 指令争取时间去读内存：

    ```Plaintext
    Cycle:      1     2     3     4     5     6
    lw  x1...  [IF]  [ID]  [EX]  [MEM] [WB]  
                                | (数据在 Cycle 4 末尾读出)
                                v  (此时可以顺利前递了!)
    add ...,x1       [IF]  [ID]  [ID]  [EX]  [MEM] [WB]  <-- 强制在 ID 阶段卡住了 1 拍！
                        (Stall)
    ```
    在 Cycle 4，硬件检测到了 Load-Use 冲突，触发 stall = 1。

    add 指令被扣留在 ID 阶段（就是我们前一段代码中 inst_PC_reg 和 instruction 被 hold 冻结住的那一拍）。

    到了 Cycle 5，lw 进入 MEM 阶段末尾，x1 的真实数据终于吐出来了！

    此时，硬件通过 Bypass 把 MEM 阶段读出的数据直接前递给正在 EX 阶段的 add 指令。

#### 2、为什么IF_ID阶段需要flush两个周期 ⚠️

因为IMeme是同步读，rdata滞后addr一拍

```verilog
always_ff @(posedge clk) begin
    if (ibus.req && gnt && ...) rdata_q <= mem[mem_addr];   // 地址在沿 K 送，数据沿 K+1 才出
end

```
地址送出去后，数据要下一拍才会出现在rdara_q
```
沿 K:   PC_reg = A            （地址送出去）
沿 K+1: rdata_q <= mem[A]      （数据出来，inst_PC 也跟到 A）
沿 K+2: IF/ID <= {mem[A], A}   （IF/ID 才锁存这条指令）
```

假设指令I_A（地址A）在EX阶段判定分支成立，目标为target,顺序取值假设PC=A,A+4,A+8……

```
沿 N:   PC_reg=A                    取 A             IF的第一拍 地址请求进入IF       
沿 N+1: rdata_q=mem[A], inst_PC=A,   PC_reg=A+4      IF的第二拍 同步读出数据
沿 N+2: IF/ID<=I_A,                  PC_reg=A+8     （I_A 进 ID）
沿 N+3: ID/EX<=I_A, IF/ID<=I_{A+4},  PC_reg=A+12    （I_A 进 EX）
沿 N+4: ★ 分支解析：PC_reg<=TARGET
        IF/ID 被 flush（清掉正要锁存的 I_{A+8}）
        ID/EX 被 flush（清掉正要锁存的 I_{A+4}）
        I_{A+12}去同步读 mem[A+12]
        I_TARGET进入IF第一拍 PC_reg=target
沿 N+5: IF/ID 被 flush（清掉刚到达锁存点的 I_{A+12}）   ← 这就是第 2 拍
        I_TARGET进入IF第二拍 mem[TARGET]
沿 N+6: IF/ID<=I_TARGET             （正确指令）

```
把它逐条对应到 IF 的三拍位置上：
```
沿	PC_reg（第 1 拍）	rdata_q（第 2 拍）	IF/ID（第 3 拍）
N+3	更新为 A+12	—	锁存 I_{A+8}
N+4	更新为 TARGET（跳转）	锁存 mem[A+12]	flush（丢 I_{A+8}）
N+5	= TARGET	锁存 mem[TARGET]	flush（丢 I_{A+12}）
N+6	= TARGET+4	锁存 mem[TARGET+4]	锁存 I_TARGET
```
个人理解：IMem对于跳转无感知，照常往IF_ID送，只能在IF_ID_reg对数据进行flush

这个和几级流水线无关，和IMem的设计有关


### 20260814

#### 1、stall和flush的区别

两者都是插入一个气泡，flush是取消指令，stall是延迟指令，

- stall(load-use冒险 core.sv:161-166)
    
    ```verilog
    // Load-Use hazard：EX 阶段的 Load 指令，其目标寄存器被 ID 阶段指令使用
    assign load_use_hazard = id_ex_ctrl_out.valid && id_ex_ctrl_out.mem_read &&
                             (id_ex_data_out.rd != 5'd0) &&
                             ((id_ex_data_out.rd == id_rs1) ||
                              (id_ex_data_out.rd == id_rs2));

    assign stall = load_use_hazard;
    ```
    - IF/ID en=0（core.sv:221）——ID 阶段那条等待数据的指令原样保持，不前进也不丢；

    - ID/EX 被 id_ex_flush = ex_flush || stall 清空（core.sv:187）——相当于在它前面插一个气泡0，防止它的"半条指令"乱跑进 EX；

    - IMem hold=stall 冻结 rdata（ifu.sv:77）——因为 PC_reg 超前 inst_PC_reg 一拍，不冻结的话 rdata 会锁存错位的下一条指令。

- flush 控制冒险 core.sv:168-186
    ```verilog
    assign id_flush = (id_pc_sel == 2'b10);           // JAL 在 ID 解析
    assign ex_flush = (id_ex_ctrl_out.pc_sel == 2'b01 && ex_branch_taken) ||
                    (id_ex_ctrl_out.pc_sel == 2'b11); // Branch/JALR 在 EX 解析
    assign if_id_flush = flush_any || flush_d;         // 2 周期窗口
    ```
    它直接把 IF/ID（及 ID/EX）控制通路里的 valid 位清 0，那条按顺序取进来的旧指令被作废。PC 已经切到跳转目标，作废的指令不会再回来。

    stall 结束后，I_k 带着它真正的执行语义继续走完流水线；而 flush 时那个气泡之后进来的是跳转目标处的指令（不是被取消的那条）。

#### 2、pipeline_reg的控制通路和数据通路

- ctrl 控制信号

    reset>flush>enable

    ```verilog
    assign ex_flush = (id_ex_ctrl_out.pc_sel == 2'b01 && ex_branch_taken) ||
                    (id_ex_ctrl_out.pc_sel == 2'b11);   // ← 用 pc_sel 判定
    assign id_ex_flush = ex_flush || stall;               // ← 结果又驱动 ID/EX 的 flush

    ```
    valid 和 pc_sel必须放在ctrl，否则flush不会清零，影响下游

- data 数据信号
    数据通路只有en,没有reset/flush，

    stall的时候，en=0,两条通路都不更新

    flush的时候，只清控制，不清数据

    id_ex_reg的crel_in在送出id_ex前已经被valid门控，valid=0时候全部归零。
    回到你的上一个问题（stall vs flush），这套分离机制让两种操作都能成立：

|操作|	控制通路|	数据通路|	语义|
|---|---|---|---|
|flush|	清 0（valid=0）|	保持（不清）|	指令作废，数据变"带标签的垃圾"|
|stall（en=0）|	保持	|保持	|整条指令冻结，等数据就绪|
|正常前进|	ctrl_in|	data_in	|指令进入下一阶段|


- 如何判断一个信号该放ctrl还是data

    - 1、flush 后它必须是已知的无效值吗？ → 是（如 valid、pc_sel，因为有人直接读它做判定/采信，不清零会出错）
    - 2、它保持旧值会不会污染下游？ → 会，且没有 valid 门控兜底 → 放 ctrl；有门控兜底 → 可放 data

#### 3、EX阶段的数据前推

- 为什么要前推

    ```
    I1: add x1, x2, x3     # 新 x1 在 EX 就出来了，但要到 WB 才写回寄存器文件
    I2: add x4, x1, x5     # 下一拍就要读 x1

    Cycle:    1      2      3      4      5
    I1:     IF     ID     EX     MEM    WB
    I2:           IF     ID     EX     MEM

    ```

    - Cycle 3：I1 在 EX 已经算出新 x1，结果正要锁进 EX/MEM 寄存器。I2 在 ID 读寄存器文件，读到的还是旧 x1。
    - Cycle 4：I2 进 EX。如果直接拿 ID 读到的旧值算，结果就是错的。

- 前推条件
    - 1、从EX/MEM寄存器前推 源1
        ```verilog
        //rs1 从EX/MEM寄存器前推（前一条指令正在MEM）
        if (mem_ctrl_out && mem_data_out.reg_write &&
                (mem_data_out.rd != 5'd0) && (mem_data_out.rd == id_ex_data_out.rs1) &&
                !mem_data_out.mem_read)
                ex_rs1_data_fwd = mem_data_out.alu_result; 
        

        // MEM 阶段有条有效指令，且它要写寄存器
        // 写的正是当前指令的源
        // 排除 Load !mem_read
        // 转发它的 ALU 结果
        ```
        为什么排除load（!mem_read）:

            Load 在 EX 阶段算的是地址，数据要到 MEM 阶段从 DMem 读回。所以 EX/MEM 寄存器里的 Load 指令，alu_result 是地址不是数据。

    - 2、从MEM/WB寄存器前推 源2
        ```verilog
        else if (mem_wb_ctrl_out && mem_wb_data_out.reg_write &&
                    (mem_wb_data_out.rd != 5'd0) && (mem_wb_data_out.rd == id_ex_data_out.rs1))
            ex_rs1_data_fwd = wb_write_data;//rs1 从MEM/WB寄存器前推（前两条指令正在MEM）
        ```
        这里没有!mem_read限制，转发值是wb_write_data,它已是最终值（mem_to_reg ? mem_rdata : alu_result），Load 的数据此时也拿到了

        为什么优先级是源1 > 源2 > 默认：

            当两条候选指令的 rd 恰好相同（都等于当前指令的源）时，最新的写者才有效：

            ```
            I1: add x5, ...      # 先写 x5
            I2: add x5, ...      # 后写 x5 —— 最新写者，会覆盖 I1 的值
            I3: add x6, x5, ...  # 读 x5
            ```

        为什么 rd != 5'd0？

            x0 硬连线为 0（写 x0 无意义），转发 x0 也是垃圾。加这个判断一方面避免把 x0 的"写入"当依赖，另一方面避免 rd==0 时恰好 rs1 也是 0 产生无意义的转发。

#### 1、为什么ex的out还要这样判断

core.sv:369-372
```verilog
    assign ex_mem_data_in.reg_write  = id_ex_ctrl_out.valid ? id_ex_ctrl_out.reg_write  : 1'b0;
    assign ex_mem_data_in.mem_write  = id_ex_ctrl_out.valid ? id_ex_ctrl_out.mem_write  : 1'b0;
    assign ex_mem_data_in.mem_read   = id_ex_ctrl_out.valid ? id_ex_ctrl_out.mem_read   : 1'b0;
    assign ex_mem_data_in.mem_to_reg = id_ex_ctrl_out.valid ? id_ex_ctrl_out.mem_to_reg : 1'b0;
```


- id_ex_ctrl_out.valid=0有两种情况

    1、ID/EX被flush 指令作废

    2、自然气泡 ID阶段本来就没有有效指令

- 设计分工：

    只有IF/ID和ID/EX需要flush，EX及之后的流水线智慧遇到有效指令或气泡，气泡由valid位自然忽略，不需要主动作废


这段只是单纯的防御性编程，去掉三目运算依然正确


#### 2、复杂的flush设计
```
沿 K:   PC_reg = X            ← 送地址
沿 K+1: rdata_q = mem[X]      ← 同步读出（第 1 条在途指令出现）
沿 K+2: IF/ID 锁存 mem[X]     ← 第 2 条在途指令同步读中

```
提供有两种情况需要冲刷

a.ID阶段识别为JAL指令，无条件跳转，冲刷两拍（id_flush）

b.ID阶段识别为JALR\BRANCH指令，EX阶段确认跳转条件符合，冲刷一拍（ex_flush）


- 1、flush_any是什么
    冲刷IF/ID门前的那条

- 2、flush_d是什么
    把flush的冲刷范围向后扩一拍，同步读里还有一条，下一拍才能到门前

- 3、为什么id_ex_flush和stall有关系
    load-use stall发生了三件事
    
|动作|	作用	|代码位置|
|---|---|---|
|IF/ID en=0（冻结）|	让被阻塞的 I_D 在 ID 阶段多待一拍，保持不动|	core.sv:222 .en(!stall)|
|ID/EX flush（作废）	|清空 ID/EX，插入一个气泡	|core.sv:188 `id_ex_flush = ex_flush|
|IMem hold（冻结）	|冻结 rdata_q，防止 PC/inst_PC 错位	|ifu.sv|


关键点：ID/EX 的 flush 就是"插入气泡"那个动作。stall 一拍的本质 = 让 I_L（Load）继续前进访存、让 I_D 停在 ID、中间空出一个 EX 位置。那个"空出的位置"就是靠 flush 清空 ID/EX 实现的。

也就是stall的时候ID/EX的输出必须是气泡，load-use时ID阶段的那条指令暂时不能进EX,要先让他停在ID,也就是向ID/EX插入气泡
