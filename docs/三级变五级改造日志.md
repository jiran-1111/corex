
# 改造完成：三级 → 五级流水线
修改的文件（3 个）
### 1. core.sv — 大幅重构为五级流水线

新增 ID/EX 流水线寄存器（id_ex_ctrl_t/id_ex_data_t 结构体，含 valid 控制位）

新增 MEM/WB 流水线寄存器（mem_wb_data_t）

EX 阶段数据前推：优先级 EX/MEM > MEM/WB > RegFile，Load 指令从 EX/MEM 转发被排除（此时只有地址没有数据）

Load-Use 冒险检测：stall 冻结 IF/ID、flush ID/EX，Load 正常通过 EX/MEM 进入 MEM

flush 逻辑：JAL 在 ID 解析（id_flush），Branch/JALR 在 EX 解析（ex_flush）

### 2. ifu.sv — 跳转控制信号拆分

从合并的 pc_sel_execute/JAL_target 拆为 ID（JAL） 和 EX（Branch/JALR） 两套信号

next_PC 优先级编码：EX 跳转 > ID 跳转 > PC+4

### 3. imem.sv — 加 hold 门控（参数化 HAS_HOLD，默认关闭保持向后兼容）

调试中定位并修复的 3 个关键 bug

|Bug|	根因|	修复|
|---|---|---|
|JALR |后错误指令被执行	IMem 同步读（rdata 滞后 addr 一拍），跳转后第 2 周期 IF/ID 仍锁存跳转前取出的陈旧指令，ex_flush 只清 1 周期	|flush_d 延迟形成 2 周期 flush 窗口（JAL/Branch/JALR 都适用）|
|Store 写入错误数据	|ex_mem_data_in.rs2_data 用了未前推的值|	改用 ex_rs2_data_fwd|
|Load-Use 停顿后指令错位	|stall 时 IMem 仍采样冻结的 PC，覆盖 IF/ID 端等待的指令（如 sw x4 被跳过）	|组合 load_use_hazard 直接门控 IMem 采样，stall 同拍冻结 rdata_q|
